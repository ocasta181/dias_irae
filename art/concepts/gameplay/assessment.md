# Parent assessment of the 24 reference-based screens

I viewed the four original character files and all 25 new successful outputs. The gallery contains 24 candidates: three Grok and three built-in scenes per source. One excluded Grok trial repeats a helmet on a neighbor; its replacement was generated from original S49 only. One temporary-capacity failure produced no image. No previous gameplay screen was supplied to either generator.

The selected character was an actual input in every completed call. Source hashes, saved prompts and output hashes are verified. Grok records expose the exact native `image_edit` input; built-in records preserve the explicit tool arguments and returned original file path. Neither provider exposes its internal reference preprocessing in full or a precise image model ID here. The art is stored unchanged; no character/background collage, crop, stretch or recoloring was made.

The built-in screens generally preserve reference medium and world cohesion better, with more convincingly compact neighbor proportions and elevated map-like composition. The first Grok pass often retains the knight but keeps a low outdoor camera or introduces realistic unarmored bodies. Those critical failures are marked `revise` on the visible cards, not presented as successful gameplay solutions. G25's pixel church and the twelve built-in scenes are pending user review, not accepted assets. No achieved numerical camera angle or production scale is claimed. Even the stronger outputs make actors larger than the requested 8–10% screen-height target.

An additional approved-board camera reference was proposed, but automatic approval review blocked its upload as outside this generation's authorized inputs. It did not execute. The successful revision used only the original selected character file and stronger text instructions. No input restriction was bypassed.
